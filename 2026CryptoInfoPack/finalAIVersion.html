1) What does a bank do today, and why do people trust it?

←→ to navigate
Core role

Banks act as trusted record-keepers and service providers.
Most “moving money” is really about securely updating records — within the bank and across multiple banks.

  • Controlled ledger Every transaction becomes a debit/credit entry in a controlled ledger.
  • Reconciliation Because multiple ledgers exist, banks must ensure they match eventually — through investigations and handling exceptions.
  • Challenges across banks Each institution has its own books, leading to reconciliation delays and operational costs.
A simple visual

Two banks = two ledgers → reconciliation to ensure they match.

Bank “A” ledger
Records debits/credits for customers and positions.
Bank “B” ledger
Also maintains its own authoritative records.
Reconciliation
Ensure both ledgers match eventually — exceptions, investigations, and resolution.
Key idea
Trust is built from controlled record-keeping + governance + audits.

2) Cryptocurrencies: The Shared Ledger Concept (before blockchain details)

Space reveal points
Traditional finance vs shared ledger

Traditional finance: each institution keeps its own ledger → reconciliation is needed.

Traditional finance
Each institution keeps its own ledger, requiring reconciliation.
→ Multiple versions of truth
Shared ledger
All participants see the same transaction state (pending/confirmed) without constant reconciliation.
→ One unified view
  • Ledger = record of ownership Crypto provides a way to maintain this record across multiple parties.
  • Trust model shift Instead of trusting a single institution’s ledger, participants trust: rules + validation mechanisms.
  • Why it matters Less “Who’s right?” — more “We all see the same record.”
Shared ledger, visualized

Participants read the same state (pending → confirmed).

Participant A
Submits transaction request.
Shared ledger
Stores common state: pending → confirmed (same view for everyone).
Participant B
Reads the same state and acts.
Key takeaway
Shared ledger reduces reconciliation pressure by aligning “the record” earlier.

What crypto changes

Crypto changes how trust and record-keeping happen.
It can replace certain system roles (shared ledger + rule-based validation), but banks still provide regulatory responsibilities and customer services.

  • Replaces: who keeps the record Shared ledger becomes the common reference point.
  • Continuation: explaining blockchain How validation works, how updates synchronize, and how “confirmed” happens.

Shared ledger can change settlement + reconciliation. Banks still wrap it with governance and customer protection.

4) Smart contracts: “rules that run” on the shared ledger

Space reveal
What is a smart contract?

A smart contract is shared business logic that runs on a blockchain.
Instead of one party enforcing rules, the network enforces the same rules for everyone.

  • Analogy: “vending machine rules” Put in $2 + choose item → machine releases item automatically. No clerk needed to interpret rules.
  • How it works (high-level) Users submit transactions → contract checks rules → updates shared ledger state (approved / rejected).
  • Why it matters Consistent enforcement + fewer disputes + automation of “if/then” policies across parties.
Open-ended question: If some rules become “code on a shared ledger,” which bank processes could be safer or faster — and which should remain off-chain?
Example smart contract functions (bank-friendly)

These are examples of what “rules that run” can do. (Not technical code — just concepts.)

1) Allowlist transfers policy
Only allow transfers to approved counterparties (addresses/participants).
2) Limits & approvals controls
Enforce transaction limits; require extra approval above threshold.
3) Mint / burn rules supply
Create/destroy tokens only when specific conditions are met (e.g., backed by deposit/liability rules).
4) Escrow & atomic swap settlement
“Either both sides happen, or neither happens” (reduce settlement risk).
Tiny pseudo-logic (illustrative)
IF receiver is allowlisted AND amount <= limit AND approvals >= required THEN transfer & mark confirmed ELSE reject (no ledger update)
Takeaway
Smart contracts = shared rules that automate decisions on the shared ledger.
